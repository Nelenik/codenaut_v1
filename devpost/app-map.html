Codenaut — what it is, in one move

A Next.js game that teaches CSS by typing one declaration at a time and watching it change a real playfield live in an iframe.

This page is a take-home map, not a checklist. It is a snapshot — generated at commit a516c92 — and can drift.

One action, end to end

The path a child walks on every task: pick a property from the basket, drop it into the editor, press Check, read the result.

1Drop zone. The chip is a whole command. In PropertyBasket.tsx the command() helper builds background-color: darkblue; — with the semicolon — and that exact string is both what the child reads on the chip and what ondragstart puts on the clipboard (command(item)). Nothing else: the property/value split lives in task.json’s basket, not in here.
2Editor. One source of truth for the CSS. LevelScreen.tsx holds childCss in state and hands it to <CssEditor value={childCss} onChange={setChildCss} />. A drop inserts at the cursor, so the chip above becomes a real declaration in the child’s input.
3Preview. The browser, not the code, judges. PlayfieldPreview keeps an <iframe> whose srcdoc is built by assemblePlayfield(html, childCss, selector) in src/lib/taskLoader.ts. That function wraps the child’s bare declarations in the task’s selector with wrapDeclarations() (and leaves already-braced CSS untouched), so color: lime becomes valid inside #target { color: lime; } and the playfield repains on every keystroke.
4Check. Computed values, never the characters the child typed. CheckButton → check(iframe, childCss, config) in src/lib/checker.ts. It reads readComputed() from the iframe’s content document (line 30), then asks valueMatches() whether the computed value matches — pixel tolerance for px, RGB tolerance for colours, geometry for border-radius: round. A pass calls recordTaskSuccess() (src/lib/progress.ts) → stars via starsForAttempts() (src/lib/stars.ts) → a ResultToast.

To change this, start here

Add a level
Make public/tasks/<world>/NN-name.html + .json (see an existing one for shape: selector, basket, expects, solution, hints), register it in src/lib/worlds.ts LEVELS, and add the tasks.<id> block to src/i18n/en.json + ru.json (text, teachBody, hints, success). The dictionary check (check-dictionaries.js) refuses a level that names a value or property the code can’t paint.
Change star scoring / hint ladder
Scoring is a small function: stars.ts → starsForAttempts(). The hint ladder is not a ladder anymore — ResultToast.tsx carries the words, the blurred answer and the ready-made solution together. A wrong check routes through checker.ts outcome rightLookWrongProperty vs nothingTyped vs the hint.
Change how a value is tested
checker.ts:49 valueMatches() is the only place “did the child get it right” is decided. Add an ExpectMode there if a task needs a different comparison (e.g. a percentage that should resolve to a specific px range). The mode rides along in task.json expects[].mode.
Change wording or add a language
All child-facing text is in src/i18n/en.json and ru.json. CSS property names and colour words can be marked with [[token]] in text, teachBody, hints; the shared renderer src/components/MarkedText.tsx paints colours and turns property names into cyan pills. The dictionary check validates that every token means something the app can actually draw.
Change how CSS is wrapped into a playfield
src/lib/taskLoader.ts → wrapDeclarations() (line 64) and assemblePlayfield() (line 71). Keep the child’s already-braced rules untouched; only bare property: value lines get wrapped in the task selector.
Run it again and verify 
npm install && npm run dev

Then open http://127.0.0.1:3000. The app reads its state from localStorage under codenaut.progress.v1 (deleting that key or opening an incognito window resets to a fresh game).

The project ships no npm test. The verification scripts live outside the repository alongside this map (check-dictionaries.js, check-learner-requests.js, check-edge-cases.js, check-language-browser.js, check-playfields.js, check-trail.js) and assume the dev server above is running. Run the dictionary check first — it guards the [[token]] markup in the dictionaries.

A practice to reuse

Test the behaviour, not the spelling. The acceptance rule for border-radius used to compare the characters the child typed against 50%; the learner tried percentages and they never passed, because a string match is the wrong test for an equivalence class. The fixed check resolves the value in the live DOM and asks “did every corner reach the middle” (geometry), so 50%, 60px and 100% are treated as the same circle (checker.ts:111 isFullyRound). On any project where an input has more than one equivalent form, compute the observable effect and compare that, not the text — it is the difference between a test that fails on a correct answer and one that survives refactoring.
